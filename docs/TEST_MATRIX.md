# Interactive test matrix

This is an operator worksheet. Repository CI does not mark any of these real-client cases as executed.

## Environment setup

Use a private staging server and synthetic accounts only. Record the gamemode commit, pinned anti-cheat dependency commit, package artifact digest, open.mp server version, client platform/build label and controlled network profile.

Run a separate observation set for each client platform/build and each network profile: `stable`, `high_ping`, `jitter`, `packet_loss`, and `low_fps`. Do not claim a profile unless it was actually observed or controlled.

Use two connected clients for spectating. Use one vehicle model per structured acceptance capture.

## Scenarios

| ID | Operator action | Expected benign observation |
| --- | --- | --- |
| walk_idle | Stand still, walk and sprint normally. | No movement evidence. |
| jump_fall_land | Jump, fall and land normally. | No movement evidence attributable only to normal movement. |
| admin_teleport | Use `/acstageteleport`. | No movement evidence after the server transition notification. |
| spawn_death_respawn | Complete normal spawn/death/respawn flow. | No evidence solely due to lifecycle changes. |
| interior_roundtrip | Use `/acstageinterior` to enter and leave. | No evidence on either transition. |
| virtual_world_roundtrip | Use `/acstageworld` to enter and leave world 9000. | No evidence on either transition. |
| vehicle_enter_drive_exit | Use `/acstagevehicle 411`, drive normally, then `/acstageexitvehicle`. | No evidence from ordinary driver activity. |
| vehicle_switch_collision | Repeat vehicle creation/exit across captures and observe ordinary collisions. | No evidence attributable only to legal vehicle transitions or collision impulses. |
| spectate_roundtrip | With a second client, use `/acstagespectate` and `/acstageunspectate`. | No evidence; original interior/world/position is restored. |
| disconnect_reconnect | Actually disconnect/reconnect and authenticate the same synthetic account. | No stale-session evidence. `/acstagetest` is not a substitute. |
| network_condition_sample | Repeat ordinary movement/vehicle activity under one declared network profile. | No evidence caused solely by that network condition. |

## Callback contract checks

After a session generates evidence, run `/acstagev2info` and verify the V2 evidence callback count increases. When a V2 strike is generated by the framework, verify the reported sequence/timestamp link. Do not change production thresholds to manufacture a strike; preserve naturally observed events for review.

Legacy callbacks remain installed. The V2 check does not log account IDs or session tokens.

## Capture and privacy

The bounded `/acstagelogbegin`/`/acstagelogend` capture emits pseudonymous `[AC-STAGE-EVENT]` and `[AC-STAGE-VEHICLE]` lines. Vehicle observations are limited to 2 Hz and 3,600 samples per capture. A capture ending from owner disconnect or context-restore failure is marked aborted.

Raw console logs may contain unrelated server metadata. Keep them local/private. Before sharing reports, use `staging_log_sanitize.py` from the anti-cheat repository at the dependency commit recorded above. Bind review metadata to the sanitized export, never the raw log.

## What CI proves

CI runs source-contract tests, compiles against pinned anti-cheat/open.mp includes, assembles the AMX package, and boots a pinned headless open.mp Linux server.

It does not connect real clients, run these scenarios, verify mobile input, estimate false-positive rates, validate network shaping, benchmark expected peak capacity or certify production readiness.
